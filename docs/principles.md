# 允夏系列原则

每个具体协议具有稳定ID、设立目的、适用对象和明确条款取舍。新增协议先说明与现有协议的关系；不得仅通过换名复制协议并暗示具有新效果。

协议ID不随显示名称改变。协议、工具、项目内容和记录格式各自维护版本。版本号用于唯一定位，不自动证明兼容；具体影响写入发布说明。

工作正文在agreements维护，日常变化由Git记录。对外审阅或采用需要固定文本，候选或正式版本在releases记录。新引用由agreement_id、version、sha256组成，不能通过额外修订字段覆盖同一正式版本。工具只接受这一引用结构。

发布事实与采用事实分开：维护者发布一份协议，不等于某个项目已采用；安装或更新Skill也不产生授权。协议发布不要求对应Skill已经实现适配，支持程度单独声明。

正式正文保持固定。新条款发布新版本；采用指南、工具规则和解释的更新不自动改变正文和旧项目绑定。停止推荐或维护时保留固定版本的可定位性。

历史资料按用途保留：固定引用、重要设计理由、未决问题和真实来源事实保留；重复归档和过程报告退出日常仓库。模板、表格和工具输出名称是管理方法，不增加协议条件。
